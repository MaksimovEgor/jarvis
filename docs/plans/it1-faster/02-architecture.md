# Architecture: Итерация 1 — Быстрее

## Что уже есть (найдено при чтении кода, 2026-09-27)
- **Перебивание в вебе уже работает:** `useWakeWord` слушает и пока Джарвис думает, и пока говорит;
  `onAlert` → `interrupt()` в `App.vue` (глушит голос, выбрасывает недосказанное). Не слушает только
  при играющей музыке (Bluetooth HFP, коммит 493fdf8). Этого ограничения не трогаем.
  **Не хватает:** пометки «прервано» у ответа и замера «замолчал через».
- **listener на asus выключен** (`jarvis-listener` inactive). Перебивание там переносится в итерацию 5:
  это тот же файл и та же работа с wake-word.
- **Озвучка уже кусками** (`speech.py`): первый кусок ≤ 60 символов, следующий синтезируется, пока
  звучит текущий. Но она стартует только после **полного** текста ответа LLM. LLM зовётся без `stream`.
- **Скрытая задержка:** после «Джарвис …» веб ждёт 1,8 с тишины (`COMMAND_PAUSE_MS`) и только
  потом шлёт команду. Метрики её покажут. Порог правим после недели замеров, не вслепую.

## Fit
- `app/main.py` — ход (`_detach`, `_answer`) отмечает время этапов и отдаёт его в событии `turn`.
- `app/metrics.py` (новый) — секундомер хода, запись в журнал, медианы. По образцу `history.py`: jsonl-файл.
- `app/agent/router.py` — новые быстрые команды: время, дата, погода, «какие таймеры».
- `app/agent/orchestrator.py` + `app/services/llm.py` — потоковый ответ облачной LLM (`stream: true`)
  с колбэком «готова фраза».
- `app/services/speech.py` — «растущая» озвучка: куски добавляются по мере прихода фраз, а конец
  объявляется отдельно.
- Hermes и локальная модель остаются **без потока**: Hermes зовётся по просьбе и долго, у локальной
  3B свой путь. Выигрыш там мал, а сложность та же.
- `web/` — строка времени под ответом (`ChatLog.vue`), замеры на клиенте (конец фразы → первый звук,
  «Джарвис» → тишина), пометка «прервано», проигрывание растущей озвучки.

## Endpoints
- `GET /tts/chunk/{job_id}/{n}` — **меняется:** для растущей озвучки ждёт, пока кусок n появится.
  Если ответ кончился раньше, отдаёт **204** («кусков больше нет»). Для обычной озвучки всё как было.
- `POST /metrics/turn` — **новый:** клиент досылает свои замеры хода (`turn_id`, конец фразы → первый звук,
  перебили ли и через сколько замолчал).
- `GET /metrics/latency?days=7` — **новый:** медианы и p90 по видам хода (быстрая команда / свой агент /
  Hermes) и по этапам. Им проверяется метрика успеха. Нужен curl, UI не нужен.

## Data
- `data/metrics/turns.jsonl` — одна строка на ход:
  `{ts, turn_id, device, kind: fast|agent|hermes|local, stages: {stt, route, llm_first, llm_total, tts_first}, `
  `first_sound?, interrupted?, silenced_after?}`.
  Серверная часть пишется в конце хода, клиентская досылается отдельной строкой с тем же `turn_id`.
  При чтении они сливаются по `turn_id`.
- Запросы: только `GET /metrics/latency` читает хвост файла (последние N дней, ~сотни строк в день)
  и считает медианы в памяти. БД не нужна.
- Ротация: файл старше 30 дней обрезается при старте ядра.

## Flow
Голосовой вопрос к агенту из веба (главный путь):

```
веб: конец фразы (t0) ─► POST /chat/audio ─► 202
ядро _detach:  STT ──stt── emit transcript
               router.try_fast ──route── (быстрая команда → ответ сразу, озвучка как раньше)
               run_agent(on_sentence) ─► llm.cloud(stream) ─ фраза 1 готова ──llm_first──┐
                                                                                      ▼
               speech.open_stream() ─► emit {speech:{id, streaming:true}} (текста ещё нет)
                                        feed(фраза 1..n) по мере прихода, синтез с опережением 1
               ответ целиком ──llm_total── speech.close() ─► emit {reply, tools, timing}
веб: fetch /tts/chunk/id/0 … n, пока не 204; первый звук (t1)
     POST /metrics/turn {first_sound: t1 − t0}
```

Перебивание: `onAlert` (t2) → `interrupt()` → `player.stop()` → звук реально стих (t3)
→ `POST /metrics/turn {interrupted: true, silenced_after: t3 − t2}`. Ответ в чате помечается «прервано».

Быстрая команда: `router.try_fast` → «Сейчас 21:47» → озвучка одним куском, без LLM.
«Погода» в router зовёт тот же `weather.run` и берёт первую строку («сейчас»), без LLM.

## External
- Облачная LLM: тот же OpenAI-совместимый `/chat/completions`, добавляется `stream: true`
  (SSE `data:` чанки, `delta.content` / `delta.tool_calls`). Переменные прежние: `LLM_BASE_URL`,
  `LLM_API_KEY`, `LLM_MODEL`. Провайдер не хардкодится. Перед Gate 3 проверю вживую, что текущий провайдер
  отдаёт поток вместе с tools.
- Open-Meteo: без изменений, через `YOUTUBE_PROXY`.
