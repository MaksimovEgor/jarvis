Как работает Джарвис: от «Джарвис» до звука

Кто слышит, кто распознаёт, кто решает, кто играет и что происходит при каждом сбое. Схема отражает код в рабочей копии, включая рефакторинг «asus — только сервер».

Карта системы

Три машины. Звук есть только у браузера: asus — сервер, point — вход снаружи. Браузер держит одно SSE-соединение, через которое приходит всё: плеер, ход разговора, объявления.

Сквозной пример: «Джарвис, включи музыку»

Подробный разбор самого частого случая. «Включи музыку» без уточнений быстрый путь нарочно не берёт, потому что подбор «по вкусу» делает Hermes. Для «Включи Queen» шаги 6–9 заменяет быстрый путь (см. ниже), и ответ приходит за 1–4 с.

Те же шаги текстом, с файлами и развилками

  1. Слышит «Джарвис» — браузер useWakeWord.ts
    Встроенное распознавание браузера (на iPhone от Apple), continuous, ru-RU. Работает, только пока вкладка видна и не идёт запись. Регулярка ловит «джарвис / джервис / жарвис / jarvis…», команда — текст после последнего совпадения.
    Нет Web Speech API — кнопки «Джарвис» нет, только тап. iOS запретил старт без жеста → кнопка «Нажми: «Джарвис»». Распознаватель передумал (слова уже нет) → onCancel, музыка возвращается.
  2. Реакция на слово — App.vue onAlert
    Сразу, не дожидаясь конца фразы: interrupt() обрывает текущую озвучку, earcon.listen() даёт сигнал, music.hold() ставит музыку на паузу (это счётчик, а не флаг).
  3. Конец команды — finishCommand
    1,8 с без новых результатов распознавателя (или 30 с максимум, или iOS сам закрыл сессию). Если есть текст — отправляется текстом через sendText, свой STT не нужен. Если сказали только «Джарвис» — включается запись.
  4. Отправка — api.ts → POST /chat/text
    detach=true: ядро сразу отвечает «принято», всё остальное придёт событиями SSE. turn_id генерирует браузер, device=web:<uuid> хранится в localStorage.
    Запрос не дошёл → в чате «Сервер ответил …», музыка отпускается.
  5. Развилка хода — main.py _detach
    Пусто → «Не расслышал.» Реплика целиком «стоп/хватит/отмена/тихо…» → мгновенно без Hermes. Иначе turns.start: ход становится задачей, и параллельно диспетчер решает, какие идущие ходы он отменяет.
  6. Быстрый путь — router.py try_fast
    Правила на регулярках. «Включи музыку / что-нибудь» — нарочно None, дальше в Hermes. «Включи Queen» здесь же вызвал бы плеер.
  7. Думает — services/hermes.py
    Поток /v1/responses. Разговор jarvis-voice-default-<ts> начинается заново после 10 мин тишины. Если в нём уже идёт ход — параллельный разговор …-p<hex>. Каждый вызов инструмента → событие tool на экран.
    502/503/504 или нет соединения до начала потока — повтор через 2, 4, 8 с. Оборванный поток не повторяется: инструменты могли уже сработать.
  8. Включает — mcp_server.py → devices.py → player.py
    Hermes вызывает MCP-инструмент отдельным HTTP-запросом и не знает устройства. Ядро помнит «чей сейчас ход» (devices.turn) и отдаёт плеер этого браузера. Хода нет (Telegram, cron) — последний браузер, где был Джарвис.
    После рестарта ядра ни один браузер ещё не появлялся → «Не знаю, где включить: открой Джарвиса…»
  9. Находит и готовит звук — youtube.py, outputs.py WebOutput
    yt-dlp через SOCKS: 5 кандидатов, для музыки — от 1 до 15 минут. Короткое скачивается в data/music/cache (LRU, 2 ГБ), длинное идёт потоком (/media/yt или HLS для Safari). Браузеру уходит снимок состояния {seq, src, start, paused}.
    Трек не загрузился — пропуск, до 3 подряд. Ничего не нашлось — «На YouTube ничего не нашлось».
  10. Озвучивает ответ — speech.py → tts.py → jarvis-tts
    Текст чистится (эмодзи, markdown), режется на куски: первый до 100 символов, каждый следующий не больше чем вдвое длиннее. Кусок 0 синтезируется сразу, следующий — пока звучит предыдущий.
  11. Доставляет — turns.emit → WebOutput.notify → SSE
    Событие turn {reply, tools, speech:{id,count}} с номером <boot>:<n>. Ответ пишется в историю вместе с turn_id.
  12. Говорит и возвращает музыку — App.vue speak → music.release
    Куски голоса играются по очереди, пока пользователь молчит. Потом release() → счётчик удержаний 0 → audio.play(). Трек закончился → /player/report {ended} → следующий из очереди (он уже скачан заранее).

Кто делает STT

После «Джарвис, команда» текст уже есть от распознавателя браузера — ядро получает текст. После тапа или «Джарвис» с паузой — запись уходит файлом, и распознаёт GigaAM v3 (e2e, с пунктуацией), int8 на CPU — 0,26 с на фразу, 0,33 ГБ RAM (на GPU было бы 0,06 с, но +0,65 ГБ RAM, а память на asus — узкое место). Запись длиннее 22 с режется по самой тихой паузе. Откат на прежний Whisper — STT_ENGINE=whisper.

Перебивание

«Джарвис» слышен и пока Джарвис думает, и пока говорит: голос замолкает, недосказанное выбрасывается (speechGeneration). Прошлый ход при этом не отменяется — решает диспетчер конфликтов.

Быстрые команды без Hermes

router.py. Только для браузера (у asus плеера нет). Текст нормализуется: нижний регистр, ё→е, без «Джарвис», «и / ну / пожалуйста» в начале. Правила нарочно узкие: сомнение → Hermes.

Параллельные реплики и отмена

Новая реплика не ждёт старые: сразу уходит в работу. Параллельно conflicts.to_cancel решает, какие из идущих (на переднем плане, той же сессии) она заменяет.

flowchart TD
  N["новая реплика"] --> R{"есть идущие ходы
на переднем плане?"}
  R -- "нет" --> Z["ничего не отменяем"]
  R -- "да" --> A{"начинается со «стоп / хватит /
не надо / передумал / забудь»?"}
  A -- "да" --> ALL["отменить все"]
  A -- "нет" --> L{"LLM_API_KEY задан?"}
  L -- "да" --> LLM["DeepSeek-диспетчер, 5 с
{cancel:[номера]}"]
  LLM -- "ответил" --> SEL["отменить выбранные"]
  LLM -- "ошибка / таймаут" --> MED
  L -- "нет" --> MED{"новая — «включи…»?"}
  MED -- "да" --> OLD["отменить прошлые «включи…»"]
  MED -- "нет" --> Z
  • Отмена = task.cancel() → закрывается поток к Hermes → Hermes прерывает агента. Без потока он доделывал брошенное и включал музыку через минуту.
  • Реплика целиком «стоп» обрабатывается до всего этого, в _detach: отменить всё на переднем плане, пауза, «Хорошо.» (~0,7 с).
  • ✕ в чате или в полоске фоновых задач → POST /chat/cancel {turn_id} — отменяет и фоновые.
  • Оборвался HTTP-запрос клиента — ход продолжается (asyncio.wait, а не await task).

Плеер: ядро решает, браузер играет

iPhone

Первый play() возможен только в жесте — любой тап «разблокирует» оба <audio> тишиной. Громкость меняется только кнопками. Длинное с YouTube — только HLS. В фоне Safari рвёт SSE.

Ссылки googlevideo

Привязаны к IP — поэтому и получение ссылки, и чтение идут через один SOCKS (rdns=True, encoded=True). 403 → ссылка берётся заново, второй раз 403 → 502.

Кнопки на экране и экране блокировки

POST /player/control: pause, resume, next, previous, stop. Перемотку браузер делает сам и сообщает позицию отчётом. ♡ / 👎 — POST /library/rate.

Сторож зависаний

Браузер: <audio> ждёт данные > 10 с, хотя должен играть → report {stalled}. Ядро: экран открыт, не пауза, нет хода, а позиция не растёт 25 с → то же. Оба пути — _on_end("stall"): следующий трек и «stalled» в журнале.

Сигналы вкуса

Лайк — файл в data/music/liked навсегда + сильный плюс; дослушал — плюс; «дальше» раньше 30 с и половины — пропуск (минус исполнителю); дизлайк — трек не звучит нигде (и в миксах), 2 дизлайка исполнителю — вес ×0.25 и вон из миксов.

Время суток

Утро 6–11 (энергия 3–5), день 11–17 (2–5), вечер 17–23 (2–4), ночь 23–6 (1–3). Настроение переопределяет: бодрое 4–5, спокойное 1–3, работа 2–3, сон 1–2. Неразмеченный трек проходит с весом ×0.5.

Профиль dj

~/.hermes/profiles/dj, hermes-dj.service, API 127.0.0.1:8643, инструменты — память, веб, история. Ключ DeepSeek и прокси скопированы из основного, токена Telegram нет. Недоступен → тот же промпт в LLM_* → без зёрен и разметки.

dj учится

Раз в сутки в 04:00 — сводка прослушиваний; dj сам пишет устойчивые выводы в свою MEMORY.md. «Я не люблю рэп» основному Hermes → music_taste_note → заметка в библиотеке → в каждом запросе к dj.

Хранилище 10 ГБ

liked/ не вытесняется; cache/ — LRU в пределах «лимит минус лайки». Лайк: cache→liked, снятие: обратно, дизлайк: удалить из кэша. Лайки у 90 % лимита — предупреждение в журнал.

Экран плеера

Мини-плеер над полем ввода (обложка, песня, исполнитель, ♡, ▶, ⏭), тап — «Сейчас играет»: обложка, 👎/♡, источник (YouTube Music / YouTube / радио), кодек и битрейт (ffprobe файла), откуда звук, перемотка ±15/30, «Дальше» из снимка SSE. Обложка — /media/cover/<id>: превью YouTube через ядро, кэш data/music/covers; цвет фона — средний цвет обложки через canvas.

Волна с настройками

Станции: user:onyourwave, занятия activity:* (12), эпохи epoch:*, жанры genre:* (161), настроения mood:*. Настройки: настроение (бодрое/весёлое/спокойное/грустное), характер (любимое/незнакомое/популярное), язык (русский/иностранный/без слов). Качество и место

Кэш — MP3 320 (~9 МБ), лайки — FLAC 24 бит / 44,1 кГц (~45 МБ). Не вышел FLAC — MP3 320. Качество в плеере — по самому файлу (ffprobe). Ref: ym-<id>, sc-<id>, YouTube — id видео (11 символов; ym-12345678 тоже 11 — проверять префикс первым).

Доставка ответа и обрывы связи

Путь браузер → Caddy → SSH-туннель → ядро рвётся (свёрнутая вкладка, моргнувший туннель, рестарт ядра). Поэтому ответ не ждут в POST — он приходит нумерованными событиями.

sequenceDiagram
  participant B as Браузер (useMusic)
  participant C as jarvis-core (WebOutput)
  B->>C: GET /player/events?device&since=boot:n
  C-->>B: state (снимок плеера)
  C-->>B: пропущенные turn после n (не старше 10 мин, последние 200)
  C-->>B: turns {active: идущие ходы устройства}
  Note over B: принятый ход не в active и итога нет → ядро перезапускалось
  B->>C: GET /chat/history
  Note over B: нашёл по turn_id → показать ответ, нет → «Ответ потерялся, повтори»
  Note over B,C: SSE упал с 5xx → переподключение через 3 с, пока вкладка видна
  Note over C: другой boot в since → все события считаются новыми
  • Досланный ответ старше 60 с показывается только текстом, без голоса.
  • Вкладку перезагрузили посреди хода — событие turns вернёт его в чат со спиннером.
  • Готовое при свёрнутой вкладке: для фоновых ходов и ошибок — пуш. Для обычного ответа пуша нет, он будет на экране при возврате.
  • Выкатка: ExecStop → wait_idle.sh ждёт /admin/busy = 0 до 120 с, SSE закрываются через 5 с.

Неточности и избыточность

Почищено

  • webpush.has_subscription — не вызывался нигде, удалён.
  • usePlayer.play(base64) — голос давно идёт только кусками по id, удалён.
  • Докстринги timers.py, mcp_server.py, player.py описывали звук через dmix на asus и listener как главного пользователя плеера — исправлены.
  • toolLabels.ts: у встроенного агента web_fetch и music показывались сырыми именами — добавлены подписи.

«Чей ход» — одна глобальная переменная

devices._turn один на всё ядро, а ходы идут параллельно. Две реплики с телефона и Mac одновременно — MCP-инструменты первой могут сыграть на втором устройстве. Пока пользователь один, риск низкий.

Сбой TTS роняет ход целиком

speech.speak внутри хода: если Vosk недоступен и файла голоса Piper нет, ответ Hermes не попадает ни на экран, ни в историю. Можно ловить ошибку озвучки и отдавать текст без голоса.
